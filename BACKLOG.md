# FrameJump — Backlog

Гипотезы и задачи, отложенные на потом. Активный план редизайна — в `docs/redesign-roadmap.md`.

## Ближе

- **Юзертест иерархии Play/стрелок.** Гипотеза: Play слишком акцентный, а главное действие экрана — покадровая перемотка. Не менять без проверки на людях.
- **Реальная линейка в масштабе для шер-карточки** — разработчику. UI стилизованной шкалы делается в PR шер-карточки; для настоящего масштаба нужна калибровка «пиксели → см» (самый простой способ — спросить рост человека, либо эталонный объект в кадре).
- **Авто-детект кадров отрыва/приземления** — разработчику на проработку. Определение позы прямо в браузере (MediaPipe Pose или аналог), видео по-прежнему не покидает клиент. Приложение предлагает кандидатов на takeoff/landing, пользователь подтверждает или сдвигает на кадр-два.

## Дальше

- **Цель** («хочу данкнуть») — пользователь задаёт цель, приложение считает нужную высоту и показывает прогресс к ней в каждом замере.
- **Сравнение двух прыжков** — два видео рядом или полупрозрачным наложением (прошлый месяц vs сегодня).
- **Слоу-мо глубже.** Чтение реального FPS из метаданных файла (например, mp4box.js) для оригиналов слоу-мо 120/240. Учесть: текущее автоопределение FPS в браузере может упираться в частоту экрана (~60 Гц) и не увидеть настоящие 240. Для «запечённых» экспортов слоу-мо (после WhatsApp/монтажа) надёжного детекта нет — там остаётся только предупреждение по физике (полёт > 0.9 с).

## Очень дальний

- **Режим тренера** — один человек замеряет команду: быстрое переключение спортсменов, история по каждому. Самый частотный сценарий использования, но другой сегмент.
