# FrameJump — Roadmap доработки дизайна

Дата: 2026-07-19. Согласовано с Аней по итогам UX-разбора экрана измерения.

**Как работаем:** вся работа идёт в интеграционной ветке `redesign`. Один пункт = один чат = одна фиче-ветка от `redesign` = один PR обратно в `redesign`. В `main` (и на живой сайт) всё уезжает одним финальным мерджем, когда редизайн готов целиком.
Каждый чат получает свой раздел этого плана как ТЗ. После мерджа PR — следующий чат стартует от свежего `redesign`. PR‑1 и PR‑2 трогают одну зону экрана (нижняя панель) — их делать строго по очереди.

**Обязательный порядок в каждом чате: план → подтверждение Ани → код.**
Прежде чем писать код, чат составляет подробный дизайн-план своего PR: все элементы (новые и изменяемые), их состояния, поведение, расположение, крайние случаи — письменно, понятным языком. Аня подтверждает (или правит — тогда правится план, не код), и только после её «ок» начинается реализация. Шаблонный промт для запуска чата — `docs/pr-chat-prompt.md`.

**Где что лежит:** канонический план — `docs/redesign-roadmap.md` в репозитории (этот файл в `tmp/plans/` — рабочая копия). Бэклог — `BACKLOG.md` в корне репозитория.

**Правила для всех PR:**
- Тач-зоны интерактивных элементов — минимум 44×44 px.
- Видео никогда не покидает браузер (никаких загрузок на сервер).
- Цвет не единственный различитель — метки дублируются иконками.
- Мобильный экран — приоритетный.

## PR-1 · `feat/marker-panel` — Нижняя панель: кнопки меток

**Проблема:** Takeoff/Landing — главные кнопки экрана, но маленькие (меньше стандарта тач-зоны). «Detected 60 FPS» занимает место, а обычному пользователю непонятен и не нужен.

**Что делаем:**
- Takeoff / Landing — крупнее, это главные CTA экрана. Тач-зона ≥ 44 px.
- Добавить иконки ↑ (takeoff) / ↓ (landing) к кнопкам и меткам — чтобы различие не держалось только на зелёном/красном.
- Убрать «Detected FPS» с экрана измерения. Автоопределение продолжает работать под капотом; значение FPS остаётся видно в карточке результата (там уже есть).
- После установки метки кнопка превращается в состояние «установлено» с номером кадра, и рядом появляются текстовые ссылки: «к кадру» (перейти на этот кадр) и «переназначить». Ссылки — вторичные элементы, кнопки не уменьшаем.
- Продумать удаление: у каждой метки своё, а не общий Clear на обе.

**Файлы:** `src/components/MarkerControls.vue`, `src/components/FpsSelector.vue` (скрыть с этого экрана), `src/App.vue`.

**Не делаем:** не трогаем Play/стрелки (гипотеза про их иерархию — в бэклоге, сначала юзертест).

**Готово, когда:** обе кнопки проходят 44×44; FPS-плашки нет на экране измерения; можно переназначить и удалить каждую метку по отдельности; всё проверено на мобильной ширине.

## PR-2 · `feat/timeline` — Таймлайн с метками

**Проблема:** попасть на нужный кадр можно только покадровыми стрелками — десятки нажатий.

**Что делаем:**
- Скраббер (полоса перемотки) под видео: тянешь — перематываешь.
- На полосе видны обе метки (цвет + иконка ↑/↓). Тап по метке — переход к её кадру.
- Зажатие стрелок ‹ › — автоповтор (перемотка кадр за кадром, пока держишь).
- На десктопе: стрелки клавиатуры ←/→ = шаг на кадр.

**Файлы:** `src/components/FrameControls.vue`, `src/composables/useVideoPlayer.ts`, `src/composables/useFrameStepping.ts`, возможно новый `Timeline.vue`.

**Зависимость:** делать после мерджа PR-1 (та же зона экрана).

**Готово, когда:** перемотка пальцем работает плавно на мобильном; метки видны на полосе и кликабельны; автоповтор и клавиатура работают.

## PR-3 · `feat/result-card` — Карточка результата

**Что делаем:**
- Переключатель единиц — сегмент-контрол `cm | in` вместо «→ in».
- Убрать крестик: карточка результата не скрывается (никаких «show more»-плашек).
- Под результатом — строка-сравнение, интересный факт: «выше среднего для любителей», «до данка не хватает X см», «средний прыжок в NBA — 71 см». Подготовить небольшой набор фактов с порогами высоты.
- Sanity-check на замедленное видео: если время полёта > ~0.9 с (высота > ~1 м) — это физически неправдоподобно; показать **ненавязчивое предупреждение** «Похоже, видео замедленное — результат может быть неверным. Загрузи оригинал видео». Не блокировать — результат показываем, просто с плашкой-предупреждением.

**Файлы:** `src/components/ResultsCard.vue`, `src/composables/useJumpCalculation.ts`.

**Готово, когда:** cm/in переключается сегментами; карточку нельзя случайно скрыть; факт показывается и меняется в зависимости от высоты; предупреждение срабатывает на нереалистичных значениях.

## PR-4 · `feat/measure-guide` — «Как правильно измерить»

**Проблема:** пользователь не знает, какой кадр считать отрывом/приземлением — а от этого зависит вся точность.

**Что делаем:**
- Небольшая ссылка «Как правильно измерить» на экране измерения.
- По тапу — модалка/страница с примерами: правильный кадр отрыва (последний кадр, где стопы касаются пола) vs неправильный, то же для приземления. Формат «верно ✓ / неверно ✗» с кадрами-картинками.
- Туда же советы по съёмке. Формулируем через принцип, а не догму:
  - **Главное — чтобы стопы и пол были чётко видны в кадре** (по ним определяется момент отрыва/касания). Ракурс сбоку обычно показывает зазор «носок—пол» лучше всего, но фронтальный тоже ок, если контакт стоп виден.
  - Камера примерно на уровне коленей/пояса, не сверху вниз.
  - Телефон неподвижен, человек целиком в кадре.
  - **60 FPS, если телефон умеет.** Причина в цифрах: ошибка ±1 кадр при 30 FPS даёт ~±4–5 см к результату, при 60 FPS — ~±2 см. Выше (слоу-мо 120/240) точнее ещё, но слоу-мо-режимы часто ломаются при пересылке — обычные 60 FPS надёжнее.

**Нужно от Ани:** кадры-примеры (можно вытащить из тестового видео).

**Файлы:** новый компонент, точка входа в `App.vue`. Посмотреть, можно ли переиспользовать паттерн `TheoryPage.vue`.

**Готово, когда:** ссылка ненавязчивая, но заметная; примеры однозначно показывают разницу верно/неверно.

## PR-6 · `feat/share-card` — Шер-карточка

**Что делаем:**
- Кнопка «Поделиться» на карточке результата.
- Выбор кадра для карточки: показываем кадр в высшей точке прыжка ± 5 кадров, пользователь листает и выбирает наименее смазанный.
- Три формата на выбор (и пока всё):
  1. Фото + маленький логотип FrameJump + цифра.
  2. Фото + шкала высоты — **только UI, без реальной привязки к масштабу**: рисуем стилизованную шкалу с цифрой высоты, красиво, но не в масштабе кадра. Настоящую линейку (в масштабе фото) делает разработчик позже. ⚠️ В описание PR обязательно включить заметку для разработчика: чтобы шкала была в реальном масштабе, нужно знать, сколько пикселей кадра = 1 см — единственная простая калибровка это рост человека (спросить) или эталонный объект в кадре.
  3. Без фото: квадрат со статистикой (высота, время полёта, дата).
- Экспорт картинки (canvas → PNG) + системный шер на мобильном (Web Share API), на десктопе — скачивание.

**Файлы:** новый компонент, `ResultsCard.vue` (точка входа).

**Готово, когда:** все три формата генерируются, кадр выбирается, шер работает на мобильном.

## PR-7 · `feat/history` — История, рекорды, новая главная

Самый крупный пункт. Возможно, в работе разобьём на 2–3 PR.

**Что делаем:**
- Хранение результатов локально в браузере (localStorage): высота, дата, FPS, один кадр-снапшот. Видео НЕ храним — обещание приватности не ломаем.
- Новая главная: сейчас там только загрузка и «как это работает» — добавляется история замеров (список/график прогресса) + личный рекорд.
- Момент празднования: новый рекорд → яркое состояние на экране результата («Новый рекорд! +X см к прошлому»).

**Открытые вопросы для дизайна:** структура новой главной; вид списка истории (карточки/график); экран празднования.

**Файлы:** `src/App.vue`, `src/components/VideoUpload.vue` (главная), новые компоненты истории, новый composable для хранения.

**Готово, когда:** результаты сохраняются и переживают перезагрузку страницы; рекорд определяется и празднуется; главная не перегружена.
